1. Peer (Узел)

Каждый участник сети — это peer , который:

    Может быть seed'ом  (имеет весь файл)
    Может быть leech'ером  (загружает файл)
    Слушает входящие соединения на определённом порту
    Поддерживает список подключённых пиров


2. Network Layer (Сетевой слой)

Отвечает за:

    TCP/UDP-соединения с другими пиром
    Отправку и приём сообщений
    Поддержку P2P-протокола  (свой или подобный BitTorrent)
    Обработку handshake , запросов чанков, подтверждений


    ✅ Используем TCP  для надёжности (можно добавить UDP позже для DHT)


3. Tracker / DHT (Система обнаружения пиров)
Вариант A: Центральный трекер

    HTTP/UDP-сервер, который хранит список пиров для каждого файла
    Peer регистрируется при старте: announce?info_hash=...&peer_id=...&port=...
    Запрашивает список пиров: GET /peers?info_hash=...


Вариант B: DHT (Distributed Hash Table — распределённая)

    Нет централизованного сервера
    Пиры хранят информацию о других пирах в распределённой таблице
    Используется Kademlia-алгоритм
    Более сложен, но полностью децентрализован


    Начни с трекера , потом замени на DHT


4. File Manager

    Разбивает файл на чанки  (например, по 256 КБ)
    Генерирует info_hash  (SHA-1 от метаданных)
    Хранит индекс чанков: <chunk_index> → <hash>
    Управляет файлом на диске: создаёт, дописывает, проверяет


5. Chunk Manager

    Управляет загрузкой/отдачей чанков
    Поддерживает очередь запросов: peer → chunk_index
    Хранит буфер загрузки  (какие чанки частично получены)
    Реализует стратегию: "сначала редкие чанки" (rarest first)


6. Hash Verifier

    Проверяет хеш каждого полученного чанка
    Если хеш не совпадает — запрашивает повторно
    Защищает от повреждённых данных


7. UI / CLI

    Командная строка: p2p download <magnet-link>
    Отображает прогресс, скорость, подключённых пиров
    Возможность остановить/возобновить загрузку
